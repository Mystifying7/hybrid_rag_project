🎙️ 1. The 30-Second Elevator Pitch
Executive Summary

"I built an enterprise-grade Smart Documentation Search Engine using a Hybrid Retrieval-Augmented Generation (RAG) pipeline. Standard search engines either rely purely on exact keywords (which miss conceptual context) or standard vector databases (which fail on specific error codes, IDs, and acronyms).

My project solves this by combining BM25 lexical search and FAISS dense vector embeddings, fusing their results using Reciprocal Rank Fusion (RRF), and refining them with a Cross-Encoder neural reranker. The final grounded context is fed to an LLM with strict guardrails to produce deterministic, hallucination-free answers with exact document citations."

🧠 2. The 2-Minute Technical Pitch: 4-Stage Architecture

"Walk me through your project architecture" — A modular, decoupled end-to-end pipeline:

Stage 1
📄

Structure-Aware Ingestion

LangChain Markdown Splitter

Instead of naive character chunking, implemented a two-pass markdown chunker that preserves document headings as metadata, maintaining the semantic hierarchy of technical documentation.

Stage 2
🔀

Dual-Index Retrieval

BM25 (Sparse) + FAISS (Dense)

Parallel execution: Sparse Index (BM25) guarantees 100% precision on technical error codes and acronyms, while Dense Index (FAISS + all-MiniLM-L6-v2) captures semantic meaning in 384-dimensional vector space.

Stage 3
🎯

Rank Fusion & Neural Reranking

RRF (k=60) + ms-marco Reranker

Fuses incompatible scoring scales via Reciprocal Rank Fusion ($k=60$), then feeds candidates to a Cross-Encoder computing multi-head self-attention directly across (Query, Document) pairs.

Stage 4
🛡️

Grounded Synthesis & UI

LLM Temp=0.0 + FastAPI REST

Top reranked chunks are formatted with metadata headers and fed to a zero-temperature LLM with strict guardrails to cite sources or refuse out-of-scope queries, visualized via an asynchronous glass-box UI.

⚔️ 4. The "Killer Argument" (Why This Beats Standard RAG)

"Why didn't you just use LangChain with OpenAI and ChromaDB like everyone else?"

❌ Standard Naive RAG (OpenAI + ChromaDB)

  • ⚠️
    Dilution of Rare Tokens: Dense embeddings smooth out exact technical identifiers, error codes (like ERR_AUTH_401), and configuration flags.
  • ⚠️
    Bi-Encoder Limitation: Compresses entire documents into isolated vectors, losing fine-grained token-to-token cross-attention interactions with the query.
  • ⚠️
    Hallucination Vulnerability: Default temperature settings and weak prompt boundaries lead to plausible-sounding fabricated answers.

✅ Our Hybrid Retrieve-and-Rerank Architecture

  • ✨
    Lexical Precision + Semantic Recall: Combines BM25 for exact keyword preservation with FAISS dense vectors for conceptual understanding.
  • ✨
    Deep Cross-Attention Reranking: Uses ms-marco-MiniLM-L-6-v2 Cross-Encoder to evaluate the deep relationships between the query and candidate chunks.
  • ✨
    Zero-Hallucination Guarantee: Strict temperature 0.0 with enforced document citations and explicit refusal on out-of-scope questions.

📊 3. Core Technical USPs (Key Takeaways to Highlight)

Component-by-component breakdown of our technological choices:

Component Technology Why It Matters
📑 Document Ingestion
LangChain Markdown Splitter Preserves document hierarchy and section headers as metadata rather than blindly cutting text.
🔍 Lexical Search
BM25 (Okapi) Prevents term-frequency saturation and accurately matches technical error codes like ERR_AUTH_401.
🧠 Semantic Search
FAISS + all-MiniLM-L6-v2 Enables fast $O(\log N)$ semantic similarity search for conceptual queries across dense vector space.
🔀 Rank Fusion
Reciprocal Rank Fusion (RRF) Non-parametric rank merging with smoothing constant $k=60$ that eliminates arbitrary score normalization.
🎯 Reranker
Cross-Encoder (ms-marco) Computes deep token-level cross-attention, avoiding the accuracy loss typical of isolated bi-encoders.
🛡️ Generation & Guardrails
Groq OSS LLM (Temp = 0.0) Enforces deterministic outputs, file citations, and zero-hallucination refusal guarantees.
⚡ Web Architecture
FastAPI + HTML/CSS/JS Fully decoupled client-server architecture with sub-second asynchronous responses and explainability inspection.
